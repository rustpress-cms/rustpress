WordPress, ohne PHP.

RustPress ersetzt WordPress und ist in Rust geschrieben. Es liest die Datenbank und den Ordner wp-content/ einer bestehenden Seite mit Block-Theme und liefert dieselben Seiten, Feeds und REST-Antworten, Byte für Byte mit einem echten WordPress verglichen.

Loslegen Herunterladen Quellcode auf GitHub 
docker run -p 3000:3000 -v /pfad/zu/wordpress:/var/www/html \
  -e RUSTPRESS_DATABASE_URL=mysql://user:pass@db:3306/wordpress \
  ghcr.io/rustpress-cms/rustpress

So funktioniert es

Keine Migration, kein Export, kein neues Datenformat. RustPress arbeitet mit dem, was eine WordPress-Seite schon hat, und beantwortet Anfragen so, wie WordPress es tun würde.

Dieselbe Datenbank

RustPress liest die üblichen wp_*-Tabellen in MySQL oder MariaDB, wie sie sind. Der Weg zurück zu WordPress bleibt jederzeit offen.

Dieselben Dateien

Block-Themes, Uploads, Übersetzungen und block.json-Dateien kommen aus wp-content/ und den WordPress-Dateien auf der Platte.

Dieselbe Ausgabe

Dasselbe HTML, dieselben Feeds, dieselben REST-Antworten, dieselben Weiterleitungen. Kern und Themes sind nach Rust portiert; einen PHP-Interpreter gibt es nicht.

Was es kann

Website, REST-API und Verwaltung, in einem kleinen Programm.

Website

Seiten, Beiträge, Archive, Suche und 404 mit dem Block-Theme der Seite, einschließlich responsiver Bilder und Galerien. Twenty Seventeen ist nativ nachgebaut.

Feeds und SEO-Grundlagen

Permalinks jeder Art, kanonische Weiterleitungen, RSS2- und Atom-Feeds, Kommentar-Feeds, Sitemaps und robots.txt.

REST-API

wp/v2 für Beiträge, Seiten, Medien, Kategorien, Schlagwörter, Benutzer und Kommentare, lesend und schreibend.

Verwaltung

wp-admin mit Anmeldung, Block-Editor, Medien, Kommentaren, Benutzern, Einstellungen, Datenschutz-Werkzeugen und Export.

Installer

Ein Installer wie bei WordPress, der die WordPress-Dateien auch selbst herunterladen und prüfen kann.

Jede Sprache

Jede Sprache, für die es ein WordPress-Sprachpaket gibt, auch Sprachen mit Schreibrichtung von rechts nach links. E-Mails gehen über SMTP hinaus.

Plugins als native Module

PHP-Plugins laufen nicht. Wichtige Plugins werden stattdessen in Rust nachgebaut und übernehmen, solange das Plugin in WordPress aktiv ist, mit denselben Einstellungen, derselben Ausgabe und demselben Verhalten. Die Dateien des Plugins bleiben einfach in wp-content/plugins.

Läuft meine Seite?

Vorher fragen: rustpress check liest mit der Konfiguration der Seite das aktive Theme und die aktiven Plugins, sagt, was davon läuft, und ändert nichts.

$ rustpress check
[ok  ] Theme twentytwentyfive: block theme, runs as it is
[ok  ] Plugin wordpress-seo/wp-seo.php 28.8: native module
[no  ] Plugin elementor/elementor.php 3.30.0: PHP plugin without a native module; RustPress ignores it

Läuft

Block-Themes, Twenty Seventeen, die sieben Plugins oben, Seiten-Caches und WP Mail SMTP (nicht nötig), jede Sprache.

Noch nicht

Andere klassische PHP-Themes, Page-Builder wie Elementor oder Divi, WooCommerce, alle anderen PHP-Plugins, Multisite, das Speichern im Customizer (Seite und Vorschau funktionieren).

Plugin fehlt?

Eine Port-Anfrage stellen oder es mit der Schritt-für-Schritt-Anleitung (englisch) selbst nachbauen.

Installation

Jedes Release bringt fertige Builds mit. Die Linux-Programme sind statisch gelinkt, eine Datei läuft also auf jeder Distribution.

  • Linux x86_64, aarch64, armv7, armv6, i686
  • .deb · .rpm · .apk
  • macOS Intel und Apple Silicon
  • Windows x64, x86, ARM64
  • FreeBSD
  • Container: amd64, arm64, arm/v7, arm/v6, 386

Server

# rustpress.toml
database_url = "mysql://wordpress:secret@127.0.0.1:3306/wordpress"
wp_root      = "/var/www/html"
listen       = "127.0.0.1:3000"
allow_writes = true   # Anmeldung, Kommentare, wp-admin
RUSTPRESS_CONFIG=rustpress.toml rustpress

Ohne allow_writes ist die Datenbanksitzung nur lesend und die Verwaltung bleibt geschlossen. TLS übernimmt ein Reverse Proxy.

Docker Compose

cp .env.example .env   # Passwort und Adresse setzen
docker compose up -d   # RustPress und MariaDB

Danach die Seite im Browser öffnen und dem Installer folgen, oder WORDPRESS_DIR auf einen bestehenden WordPress-Ordner zeigen lassen und dessen Datenbank-Dump einspielen.

Shared Hosting (CGI)

Bei Hostern, die nur Apache mit CGI anbieten, kommt das statische Programm nach cgi-bin/. RustPress erkennt den CGI-Modus selbst, liest die Datenbankeinstellungen aus wp-config.php und übernimmt die Seite über .htaccess. Auf leerem Webspace lädt der Installer die WordPress-Dateien von wordpress.org und prüft ihre Prüfsummen.

Aus dem Quellcode

git clone https://github.com/rustpress-cms/rustpress
cd rustpress
cargo run --release -p rustpress-server

Alle Einstellungen gehen auch als RUSTPRESS_*-Umgebungsvariablen; siehe das README.

RustPress ist experimentell. Es ist gegen WordPress 7.1.4 getestet und betreibt eine echte Seite im Produktivbetrieb, aber rechne mit Ecken und Kanten. Sichere Datenbank und WordPress-Dateien, bevor du es auf eine Live-Seite loslässt.

Klassische PHP-Themes außer Twenty Seventeen und PHP-Plugins ohne natives Modul laufen nicht.
